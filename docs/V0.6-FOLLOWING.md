# v0.6: multiple followed games

This release adds four independently monitored games and two independently journaled WLED outputs to both ESP32 and Fire TV. Upcoming games wait until live play. A first connection or reconnection establishes a baseline and skips historical events.

## ESP32 setup

1. Select an upcoming or live game in SCORES, open GAME → FOLLOWING, and tap FOLLOW. Repeat for up to four games. Following a game initially enables its display only.
2. Open the ESP32's existing local web address. The new Followed games section is at the top. Set target A and B to different WLED IP addresses (leave unused targets blank).
3. For each game, choose device display, sound, A/B/both/no lights, Away/Home/Both, TV delay (0–90 seconds), and solid goal colors or DDP effects. Save each game.
4. Enable the SOUND master switch and configure team sounds if goal audio is wanted. Then START ALL, on the touchscreen or web page.
5. STOP ALL cancels queued reactions and restores original WLED scenes. Changes and manual previews remain blocked while monitoring or restoration is pending.

The FOLLOWING view displays the games with Device display enabled. Browsing all scores remains available. Output settings are edited through the web page; the touchscreen provides follow/start/stop and status. A paged web interface and automatic full-screen logo carousel are later iterations, not part of v0.6.

Use the **cyd_ili9342** firmware for Geoff's previously validated board. Existing panel rotation, touch calibration, 12/24-hour format, and 16 KiB loop stack are retained. The separate cyd (ILI9341) and cyd_st7789 variants remain available.

## Fire TV setup

Select a game under NHL SCORES, open GAME, and choose FOLLOW SELECTED. Followed-games controls appear above the existing single-game controls. Save/connect the first WLED IP under LIGHTS, then assign it to target A in GAME. Repeat with a second IP for target B. Each followed game's controls cycle its output choices, team side and TV delay; DDP mode exposes individual event toggles. Enable goal audio on SOUND if wanted, then START ALL.

STOP / RECOVER ALL cancels monitoring and retries any saved light restoration. Controls cannot edit an active configuration. Ordinary app restart does not silently arm followed games. Opening the app recovers interrupted multi-game light scenes; keep the app/service running until recovery succeeds.

## Shared behavior

- Maximum four games, two distinct WLED targets, eight waiting events per target. A single game may drive both targets, and several games may share one target.
- Every game keeps its own baseline, delay and 20-second cooldown. Polling rotates through games, one request approximately every 6.25 seconds: four games are checked approximately every 25 seconds, plus network latency.
- Shared-target effects finish their eight-second run before another begins. Waiting priority is goal, game end, shootout, overtime, period start, power play, period end; equal priorities retain arrival order. A full queue accepts a higher-priority event by evicting a lower-priority entry. Waiting events expire after 20 seconds, measured after the configured TV delay.
- Snapshot each target once before its first effect. Chained effects preserve that original snapshot until the queue is empty. A failed restore keeps the target's journal and retries; it never replaces the original scene with an intermediate celebration.
- Solid mode reacts to goals. DDP supports the seven event types and streams the whole target at 20 fps, maximum 600 LEDs. DDP owns the whole device during an effect.
- Display, audio and light outputs are independent. Goal sounds enter a separate single-player queue after the game's TV delay. A busy light target may therefore show its effect after the corresponding sound. Sound obeys the master switch and existing team sound profiles.
- Reboot saves following preferences but starts multi-game monitoring disarmed. Starting multi-game monitoring clears the legacy single-game resume request. Single-game monitoring and multi-game monitoring cannot run together on the same controller.
- Use one GlowDeck controller per WLED target at a time; ESP32 and Fire TV do not coordinate ownership across separate physical controllers.
- NHL polling and LAN HTTP latency affect reaction and restoration timing. No scheduled-time-only kickoff assumptions; actual feed state governs eligibility.

## Verification

Automated checks cover independent game engines, priority/FIFO, queue overflow and expiry, cancellation, wraparound, output/config persistence and validation, plus the existing event/audio/DDP regression suites. All three firmware profiles and the Android APK must compile in CI before release.

Hardware acceptance remains required:

1. Follow two upcoming games; confirm no effects before their live baseline/start.
2. With A and B on different scenes, trigger separate games and confirm each target restores its own original scene.
3. Route both games to A; confirm no overlapping streams and original scene restoration after the queue drains.
4. Disable display for one game and lights for another; confirm only their selected outputs react. Verify sound master OFF is silent.
5. Disconnect WLED during restoration, STOP, then reconnect: recovery retries without replaying events. Reboot mid-effect and verify recovery without re-arming.
6. Verify touch alignment, unchanged orientation, 12/24-hour preference, and no full-screen redraw when content is unchanged.
